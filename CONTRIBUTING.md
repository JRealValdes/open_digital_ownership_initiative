# Contributing to the Open Digital Ownership Initiative

Thank you for helping improve this proposal. This repository is a living
document: ideas should be challenged, refined, and made more precise over
time.

## Ways to contribute

1. **Open an issue** to report ambiguities, propose scope changes, or
   discuss design trade-offs before writing a pull request.
2. **Open a pull request** with concrete improvements to the framework,
   glossary, FAQ, or supporting documents.
3. **Propose an RFC** for larger changes (new ownership modes, protocol
   sketches, incentive models, legal considerations). See
   [`rfcs/README.md`](rfcs/README.md).

## Principles for contributions

- Prefer clarity over rhetoric. Keep the tone professional and realistic.
- Define terms before using them. Update the [glossary](docs/glossary.md)
  when introducing new concepts.
- Distinguish **normative** statements (what the model requires) from
  **illustrative** examples (one possible implementation).
- Prefer small, focused pull requests over large rewrites.
- Do not introduce sensational framing, conspiracy narratives, or
  marketing language. Argue from consumer rights, incentives, and
  technical feasibility.

## Document conventions

- Primary language: **English** (for international review).
- Framework versioning follows semantic intent:
  - **Patch** — clarifications, wording, typos.
  - **Minor** — additive concepts that do not overturn existing ones.
  - **Major** — breaking changes to the ownership model.
- Update [`CHANGELOG.md`](CHANGELOG.md) when a change is accepted.

## Pull request checklist

- [ ] The change improves precision, completeness, or readability.
- [ ] New terms are defined in `docs/glossary.md` if needed.
- [ ] Examples are clearly marked as non-normative when appropriate.
- [ ] The logical order of the framework still holds (no forward
      references to undefined concepts).
- [ ] `CHANGELOG.md` updated for user-visible changes.

## Code of conduct (lightweight)

Assume good faith. Critique ideas, not people. Keep discussion focused on
ownership rights, technical design, and practical adoption.
